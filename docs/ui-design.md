# 授权中心界面设计

## v0.2.0 方向

服务对象是管理 AI 工具权限的自部署用户；主要工作是连接服务、明确授权范围、追踪并撤销使用。视觉要让用户快速看清「哪个服务、什么权限、是否仍然有效」。

本轮使用 frontend-design 与 UI UX Pro Max。检索中的 FAQ 落地页、霓虹安全终端风格不适用于实际控制台，未采用。改用明亮的权限工作台：浅色侧栏、蓝色权限标识、明确的资源与状态、服务目录和记录列表各有结构。

| Token | 值 | 用途 |
|---|---|---|
| Canvas | #F7F8FA | 主工作区 |
| Surface | #FFFFFF | 卡片、表单、顶栏 |
| Ink | #182230 | 主要文字 |
| Muted | #5D6879 | 说明文字 |
| Accent | #315DE9 | 主要操作、选择、品牌 |
| Border | #E4E8EF | 结构分隔 |

字体：Manrope 用于英文品牌与页面标题；中文与正文采用系统苹方 / 微软雅黑无衬线字体。字体本地托管并提供系统回退，不使用 CDN。字体字号 12/13/14/16/20/28，正文行高至少 1.5；表格数字使用 tabular-nums。

布局左对齐。主视觉是服务图标、权限标签与连接状态组成的目录，不加入装饰大数字、虚构活动或安全评分。

```text
┌ 工作空间 ┬ 位置路径                            使用文档 ┐
│          ├ 页面标题 / 操作                              │
│ 目录     │ 说明文字                                     │
│ 我的连接 │ 搜索与筛选                                   │
│ AI 授权  │ Gmail                 GitHub                 │
│ 操作记录 │ SSH                   Instabox               │
│          │ 计划接入：飞书 / Instagram                    │
│ 使用帮助 │ 权限说明                                     │
└ 管理员   ┴──────────────────────────────────────────────┘
```

目录使用两列服务面板与独立的后续接入区。我的连接使用带图标和资源的横向条目；授权条目突出状态、资源和工具；审计保留表格与筛选。空状态提供明确下一步。连接表单显示服务上下文、字段帮助和提交状态，令牌只展示一次且关窗清除。交互维持现有 API 与安全边界。

## 交互与验收

- 搜索、筛选、键盘操作和状态提示必须真实可用，不添加无动作按钮。
- 深链接继续使用 catalog/connections/grants/audit；导航显示选中状态，切页后焦点可预测。
- 操作状态以文字配合颜色表达；未测试连接不标为健康。
- 桌面控件点击区至少 36px，手机主要操作至少 44px。对话框可取消、可滚动，焦点不被底栏遮挡。
- 搜索与筛选可清空；请求失败保留重试入口，不回显凭证；不使用 innerHTML、外部脚本或客户端凭证持久化。
- 支持 375/768/1024/1440px、放大文字和减少动态效果；保留可见焦点、表单标签与屏幕阅读器语义。
- 截图复核后执行真实 Chromium 流程、输入边界测试与授权核心回归；在 three 的隔离环境验证，再更新发布与部署材料。

## 交互约定与发布门槛

- 导航只使用现有四个 hash 页面；帮助入口指向真实说明。连接目录的可连接数量只统计后端支持的 provider，计划接入项独立说明，不纳入可用数量。
- 已配置连接不是已验证连接；测试状态来自本次明确测试结果，页面刷新后不暗示持续健康监测。授权按服务端 expires_at/revoked_at 判断，不能仅靠颜色表达可用性。
- 弹窗使用原生 dialog；Tab 不逃到背景，Escape 与取消可关闭，关闭后焦点返回触发控件。加载中避免重复提交，关闭或切换弹窗后忽略旧请求的界面写入。
- 令牌仅签发时展示，复制成功要有文字反馈；复制失败提供手动选择入口。关窗销毁输入节点，不写浏览器 storage、URL、控制台或截图。秘密字段在创建请求后及时清空，不因错误消息反射到页面。
- 用户、连接、资源与上游文本使用 textContent/安全节点 API，禁止 innerHTML。登录和退出表单保留同源来源信息；页面 referrer meta 不得覆盖服务端 same-origin 策略为 no-referrer。
- 搜索筛选改变结果时保留输入焦点；清空后恢复全部数据。记录表格在窄屏使用局部滚动，不能把整个页面撑宽。
- 验收使用独立浏览器 fixture，不能把真实账号、邮件、私钥或管理令牌放入公开截图。截屏只证明视觉状态，交互、安全与错误处理需要浏览器断言。

v0.2.0 已完成 three 隔离 staging 的浏览器和容器验收，并通过 GitHub Actions 发布公开 amd64 镜像；最终发布状态以 [验收记录](validation.md) 为准。v0.2.1 修复可信 TLS 反向代理下管理请求的外部来源识别；当前 v0.3.0 增加运行诊断与授权生命周期操作，响应式和交互验收结果见验收记录。

### 审计 CSV 导出

审计工具栏提供关联标签的开始/结束日期输入与“导出 CSV”。日期采用浏览器本地时区，转换为 `after`/`before` Unix 秒；今天的结束时间截断到当前时刻。留空默认最近 31 天，范围不得倒置、超过 31 天或包含未来日期，字段变更与提交均反馈验证结果。下载使用管理员 Cookie 认证，不把管理令牌放入地址或浏览器存储；响应作为 Blob 下载，不解析或展示 CSV 内容。下载失败保留日期并给出反馈。

日期交互参考 ui-ux-pro-max 的 `date range inline validation` UX 搜索结果：可见且关联的标签、字段变更验证与明确状态反馈。浏览器 fixture 校验下载、查询参数及假凭证不出现在下载文件中，随后删除下载文件；完整浏览器验收由隔离测试环境运行。
