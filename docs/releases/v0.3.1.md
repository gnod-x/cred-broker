# Cred Broker v0.3.1

本版交付 2026-11-25 改造计划的第一批 T00–T03，聚焦启动正确性、HTTP 信任边界和授权操作一致性；后续 T04–T14 仍待执行。

- 已有数据库在监听前校验权限、属主、严格 32 字节主密钥，以及全部 legacy/scoped 密文和 JSON。缺 key、错 key、损坏或部分安装失败关闭，不生成替代 key。空库配对明确为 `unproven`。
- 管理与 MCP 共用精确 Host/Origin；正式入口不信任任意转发头。实际请求体默认最多 65536 字节，读取总期限 10 秒，超限/超时分别为 413/408。
- 本地连接、授权、撤销和审计同事务。远端动作后无法记录结果时返回 `outcome_unknown`、`retryable=false`，MCP 标记 `isError`，提示不得自动重试。
- 一次性令牌签发期间防重复提交和误关闭；响应丢失或超时明确说明未知结果，刷新核对后撤销或重签，令牌不写浏览器持久存储。
- 发布流程先验收同一个候选镜像，再推送、按摘要拉回并复验；恢复演练使用备份前原始 token 完成 HTTP 发现、模拟调用和撤销。

## 安装与升级

镜像 `ghcr.io/gnod-x/cred-broker:0.3.1`，Linux amd64。沿用原 Compose 项目和数据卷，先备份完整数据库状态、配对主密钥及配置。外部 LAN、域名或自定义映射端口必须在 `CB_ALLOWED_ORIGINS` 精确登记；默认 localhost:8765 仍可用。环境变更用 `docker compose up -d --force-recreate`，不能仅 restart。

```sh
docker compose pull cred-broker
docker compose up -d --no-build cred-broker
docker compose exec cred-broker python -m cred_broker doctor
```

重启后管理会话失效，使用原管理凭证重新登录。启动校验失败时恢复正确配对并核对权限，不能删除数据库或重新生成 key。备份、恢复和回滚见[集成指南](../integration.md)。
