# Cred Broker v0.3.0

本版让自部署项目更容易接入、诊断和维护短期工具授权。

- 管理员可查看部署诊断、连接最近测试状态，并按剩余有效期筛选授权。
- 授权可按原范围原子重签发。签发成功时，旧令牌立即失效，新令牌只返回一次。
- 签发窗口提供 MCP 配置和协议自检示例。Provider schema 描述可接入字段与工具约束。
- 操作记录支持按日期导出脱敏 CSV，并限制范围、处理表格公式前缀。
- 新增只读 `doctor` 和 `backup-check`，检查本地配置、独立备份完整性及主密钥配对。
- 管理页面使用可注销的短期会话，并限制登录尝试频率。通过 TLS 反向代理访问时仍需配置外部来源。

## 安装与升级

公开镜像 `ghcr.io/gnod-x/cred-broker:0.3.0` 支持 Linux amd64。首次部署见 [README](https://github.com/gnod-x/cred-broker/blob/v0.3.0/README.md#用-docker-compose-部署)。

已有部署先备份数据卷、配对主密钥和配置。更新到 `v0.3.0` 的 Compose 文件后，沿用原项目名和数据卷执行以下命令。

```sh
docker compose pull cred-broker
docker compose up -d --no-build cred-broker
docker compose exec cred-broker python -m cred_broker doctor
```

升级后管理员需重新登录。`CB_PUBLIC_ORIGIN` 保持实际反向代理的精确 origin，自定义项目名或覆盖文件继续用于以上命令。备份预检和恢复演练的步骤见[集成指南](https://github.com/gnod-x/cred-broker/blob/v0.3.0/docs/integration.md#备份与恢复演练)。
